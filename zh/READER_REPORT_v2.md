## 1. P0 必修清单 (42 条 · 事实错 & 数据错 & 诚信问题)

### 1.1 硬件与算力数据 (R12 · 4 处系统性错误)

- **P0-01** [Ch09/Ch12] **H100 FP8 峰值算力**: 全书写 989 TFLOPS, 实际 **1979 TFLOPS** (稀疏), 998 (稠密). 差一倍.
- **P0-02** [Ch12] **B200 FP4 峰值**: 全书写 2.5 PFLOPS, NVIDIA 官方 **5 PFLOPS** (dense).
- **P0-03** [Ch09] **V100 支持 TF32**: 错. **TF32 是 Ampere (A100) 起才有的**, V100 是 Volta 无 TF32.
- **P0-04** [Ch12] **B200 TDP 700W**: 错, 实际 **1000W** (SXM 版).

### 1.2 归属/公司/时间事实错 (跨章共识)

- **P0-05** [Ch15 · R15] **PivotalPath 归属 Goldman Sachs**: 错. PivotalPath 是**独立对冲基金研究公司** (Jon Caplis 创办), 与高盛无股权关系.
- **P0-06** [Ch15 · R15] **蚂蚁量化交易 0.0001% 数据**: 无公开出处, 数字不可信, 删除或加"来源存疑"标注.
- **P0-07** [Ch16 · R19] **KubeFATE 归属阿里**: 错. FATE/KubeFATE 由 **WeBank (微众银行)** 开源.
- **P0-08** [Ch18 · R8] **奔驰全球首例 L3**: 错. **Honda Legend (2021.3)** 才是全球首个获批 L3, 奔驰是欧洲首例.
- **P0-09** [Ch16 · R8] **DiffDock 论文年份 2023**: 错, ICLR **2023 发表, 2022 arxiv 首发**, 按引用规范应写 arXiv 2022 / ICLR 2023.
- **P0-10** [Ch16 · R16] **DSP-1181 终止**: 全书只提"进入 Ph1", 未说明 **2020 年因缺乏疗效已终止**, 属选择性叙述.

### 1.3 数量级错 (BCI/量子章节)

- **P0-11** [Ch18 · R17] **Intel Hala Point Loihi 2 芯片数**: 全书写 24 颗, 实际 **1152 颗** (差 **48 倍, 一个数量级**). 严重.
- **P0-12** [Ch18 · R18] **Neuralink N1 通道数**: 全书写 2048, 实际 **1024 (64 探头 × 16 触点)**. 差 2 倍.

### 1.4 数学定义/算例错 (数学章节, R1/R2 提出)

- **P0-13** [Ch02.01 · R1] **tr(A) 算例错**: "对角元 1,4,9 → tr=14" 但同页矩阵对角是 1,5. 且**迹对非方阵未定义**是范畴错误. 需重写算例.
- **P0-14** [Ch01 · R2] **unit roundoff u 定义位错**: p=24 时, u 应为 **2^{-p} = 2^{-24}** 或 **2^{-(p-1)}/2**, 书中写 2^{-(p+1)} 与给定值矛盾. 术语与公式对不上.
- **P0-15** [Ch02 · R1] **行/列向量约定不一致**: 全书交替使用, 读者跟不上. 需 §Preliminaries 定一次, 全书统一.
- **P0-16** [Ch02.01 · R1] **向量空间公理少列**: 加法结合律 (a+b)+c=a+(b+c) 缺失, 是标准公理漏项.

### 1.5 ML/DL 算法机制错

- **P0-17** [Ch03 · R3] **K-Means 空簇处理缺失**: 空簇导致除零, 必须写 "随机重初始化 / 取最远点" 处理.
- **P0-18** [Ch04 · R3] **REINFORCE 梯度符号错**: 更新方向写反, 会导致 loss 上升. 严重误导.
- **P0-19** [Ch05 · R2] **IRLS 等价推导跳步**: L1/Huber 到 IRLS 权矩阵推导直接给结果, 中间 3 步需补齐.
- **P0-20** [Ch06 · R4] **UAT 推导跳步**: 通用逼近定理只给结论, 缺 Stone-Weierstrass 或 Cybenko 引理骨架.
- **P0-21** [Ch07 · R7] **卷积 dilation 输出公式缺失**: dilation 版 output = floor((H + 2p - d(k-1) - 1)/s + 1), 全书公式漏 d.
- **P0-22** [Ch07 · R7] **LLaVA Token 数 256/576 自相矛盾**: 需统一, LLaVA-1.5 用 576 (24×24), LLaVA-Next 是 2880.

### 1.6 NLP 章节

- **P0-23** [Ch08 · R5] **BPE 手算错**: "e s 出现 6 次, w-e 8 次", 实际语料上手算相反. 全表重算.
- **P0-24** [Ch08 · R5] **WordPiece = 似然最大**: 不精确, WordPiece 是 **PMI 打分 (log P(AB)/P(A)P(B))**, 与似然不等价.

### 1.7 LLM/CV 系统章节

- **P0-25** [Ch09 · R6] **vLLM 比 TRT-LLM 快 10-30%**: 2024 早期数据, **2026 已趋平甚至 TRT-LLM 略优**, 建议删除比较或换基准.
- **P0-26** [Ch09 · R6] **Moonshine 全 CPU 实时** 类描述夸大, 需引官方 benchmark 或降调.
- **P0-27** [Ch07 · R7] **DDPM/Flow Matching 描述**: "Flow Matching 是 DDPM 的推广" 表述失真, 应作为**独立 CNF 框架**介绍.
- **P0-28** [Ch18 · R8] **NeRF 作为当前 SOTA**: 已过时, **3D Gaussian Splatting (2023)** 才是当前主流, 需替换.

### 1.8 分布式/系统章节

- **P0-29** [Ch10 · R10] **fork() 复制内存**: 现代 Linux 是 **Copy-on-Write (COW)**, 只共享页表, 写时才复制. 必改.
- **P0-30** [Ch14 · R14] **Redlock 推荐** 违反 **Kleppmann 2016 分布式安全性反驳**. 需加"存在争议"或换 fencing token 方案.
- **P0-31** [Ch14 · R14] **checkpoint 体积算错**: 70B FP16 模型 checkpoint ≈ **140GB 权重 + 280GB Adam 状态 + ... ≈ 980GB**, 书中写 560GB.

### 1.9 MLOps/推理章节

- **P0-32** [Ch13 · R13] **INT4 相对 INT8 吞吐翻倍**: 不成立. **memory bandwidth bound** 时才近似, compute bound 场景相同. 需限定条件.
- **P0-33** [Ch13 · R13] **FP8 训练用 loss scaler**: 错. FP8 用 **per-tensor delayed scaling** (Transformer Engine), 与 FP16 loss scaler 机制不同.
- **P0-34** [Ch12 · R12] **Cactus 工具**: 高度疑似 AI 幻觉工具名, 无公开仓库, 需**验证或删除**.
- **P0-35** [Ch12 · R12] **Docker Compose GPU 语法**: `runtime: nvidia` 已过时, 现在用 `deploy.resources.reservations.devices` 结构.

### 1.10 生物 / 量子 / BCI 章节

- **P0-36** [Ch16 · R16] **ESM-1 参数量 13 亿 vs 650M 混淆**: **ESM-1b = 650M, ESM-1v = 650M, ESM-2 有 15B 版本**. 书中错标为 ESM-1.
- **P0-37** [Ch16 · R16] **ESM-2 训练 token 15B**: 错, 官方论文 **60B token** (UniRef50).
- **P0-38** [Ch16 · R16] **ESM-3 esmGFP "远超自然界亮度"**: 实测**仅 sfGFP 50%**, 严重高估.
- **P0-39** [Ch18 · R18] **中国 BCI 三家公司混淆**: **脑虎 (侵入式) / 强脑 BrainCo (非侵入) / NeuroXess (侵入)** 是三家不同公司, 全书当作同一实体.
- **P0-40** [Ch18 · R18] **Willett 2021 & 2023 Nature 论文**: 是两个不同范式 (手写 vs 语音), 全书当作同一工作引用.

### 1.11 教材诚信问题 (R25)

- **P0-41** [README · R25] **Status 列 stub 标 Available**: 学术诚信瑕疵. 需诚实标注 "Stub / Draft / Complete".
- **P0-42** [Ch15/Ch18 · R25] **零 Coding Task 章节**: 至少各补 3-5 道编程题, 保持章节完整性承诺.

## 5. 全局建议 (给主编 5 条)

### 建议 1: 建立"数据事实核查表"

集中所有 42 条 P0 中涉及的**硬件常数、参数量、论文年份、公司归属、算力数字**建单一 fact-sheet, 每个数字标注**出处 URL + 抓取日期**. 未来修订时先动 fact-sheet, 再全书 sed 替换. 避免 "H100 FP8 989" 这类错误反复出现.

### 建议 2: 章节完整度分级明示

README Status 列诚实分 4 级:
- **Complete**: 全节 + 习题 + 代码 + 参考
- **Draft**: 全节但习题/代码不全
- **Stub**: 只有大纲和 1-2 段
- **Planned**: 未开始

不要把 Stub 标 Available (R25 明确指出诚信问题).

### 建议 3: 引入 "领域校对人 (Domain Reviewer)" 机制

22 份反向报告揭示: **主编无法覆盖 22 个领域**. 建议每章挂一名领域校对人 (可以是本书目标读者), 后记页署名. 好处:
- 事实错误进一步降低
- 增加读者信任
- 反向证明 AI 味不重 (有真人把关)

### 建议 4: 每章加"作者按"专栏

R24/R25 的共同诉求. 每章开头 200 字 *作者:* 引言, 讲**为什么这一章这样组织 / 我在业界看到的实际用法 / 我个人的取舍**. 一处即可显著降 AI 味.

### 建议 5: 用 v2.0 全新校对流程

未来所有新章节按以下流程:
1. **草稿** → LLM 生成 + 主编改写
2. **反向纠错** → 至少 2 位目标读者 (专业 + 入门)
3. **fact-check** → 对照 fact-sheet 逐条核实
4. **代码运行** → 所有代码本地跑通截图归档
5. **发布** → 标 Complete

不走完不标 Complete.
