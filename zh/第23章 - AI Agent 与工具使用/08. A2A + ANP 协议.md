## 一 · 一句话总览

> **Agent 协议 2025 = 3 大协议**: **MCP (Anthropic 2024-11, 工具协议)** → **A2A (Google 2025-04, Agent-to-Agent)** → **ANP (Agent Network Protocol, 跨域互联)**。IBM 的 ACP 已于 2025-08 并入 A2A (Linux Foundation 治理), 不再是独立协议。三大协议解决的是不同连接对象的问题。

---

## 二 · 心智模型

把 Agent 协议想成"互联网协议"演进:
- **HTTP** (1990) = 文档传输
- **REST API** (2000) = 资源访问
- **GraphQL** (2015) = 灵活查询
- **MCP** (2024) = LLM 工具访问
- **A2A** (2025) = Agent 协作
- **ANP** (2025) = Agent 网络

**每一层都建立在上一层之上**。

### 第 2 段 · MCP (Anthropic 2024-11) (10 分钟)

**全称**: Model Context Protocol

**核心思想**: 把 LLM 与外部工具 / 数据**标准化连接**。

**架构**:
```
LLM ←→ MCP Client ←→ MCP Server ←→ 工具 / API / DB
```

**3 大组件**:
- **MCP Host**: Claude Desktop / IDE
- **MCP Client**: 与 server 通信
- **MCP Server**: 暴露工具 (Python / TS 实现)

**协议特性**:
- JSON-RPC 2.0
- stdio / HTTP+SSE / Streamable HTTP
- 三种原语: Tool / Resource / Prompt

**示例**:
```python
# MCP Server
from mcp.server import Server

app = Server("weather")

@app.tool()
async def get_weather(city: str) -> str:
    return f"Weather in {city}: sunny"

# MCP Client
from mcp.client import Client

client = Client(app)
result = await client.call_tool("get_weather", {"city": "Beijing"})
```

**Ch23 §04 已覆盖**, 本节扩展。

### 第 3 段 · A2A (Google 2025-04) (10 分钟)

**全称**: Agent-to-Agent Protocol

**核心思想**: 解决 **Agent 之间**通信, 不只是 LLM 调用工具。

**与 MCP 区别**:
- **MCP**: LLM ↔ Tool (工具调用)
- **A2A**: Agent ↔ Agent (协作)
- **MCP 解决"如何访问工具"**
- **A2A 解决"如何与其他 Agent 协作"**

**关键概念**:
- **Agent Card**: JSON 描述 Agent 能力 (类似 OpenAPI)
- **Task**: 任务对象 (state, message, artifact)
- **Push Notifications**: 异步事件
- **Streaming**: 长任务流式传输

**协议栈**:
- HTTP(S) 之上三种传输: JSON-RPC 2.0 (默认) / gRPC / HTTP+JSON (REST)
- Server-Sent Events (SSE) 用于流式传输
- 0.3 规范 (2025-06) 起正式支持三种传输, 客户端与服务端可协商

**示例**:
```json
// Agent Card
{
  "name": "Research Agent",
  "description": "Performs web research and analysis",
  "url": "https://research-agent.example.com",
  "skills": [
    {"id": "web_search", "description": "Web search"},
    {"id": "summarize", "description": "Summarize text"}
  ],
  "auth": {"type": "oauth2"},
  "version": "1.0"
}
```

**治理与生态**:
- 2025-04 由 Google 发布, 获 50+ 企业支持 (AWS / Microsoft / Salesforce / Atlassian 等)
- 2025-06-23 捐入 Linux Foundation, 更名 Agent2Agent Protocol Project, 开放治理
- 主流框架集成 (LangGraph / AutoGen / CrewAI 等)

### 第 4 段 · ANP (Agent Network Protocol, 2024 发起) (8 分钟)

**核心思想**: 解决 **跨域 / 跨组织** Agent 互联。

**与 A2A 区别**:
- **A2A**: 同一信任域内 Agent 协作
- **ANP**: 跨域 / 跨组织 Agent 网络 (类似 HTTP + DNS)

**核心特性**:
- **去中心化**: 基于 DID (Decentralized Identifier, 自研 did:wba 方法)
- **协商**: 自动 Agent 发现 (类似 DNS)
- **加密**: 端到端加密通信
- **互操作**: 跨协议转换

**架构**:
```
Agent A  ←→  ANP Gateway  ←→  Agent B
             ↓
      DID (did:wba, 身份)
             ↓
      ADP (Agent Description, 能力描述)
```

**适用场景**:
- 跨企业 Agent 协作
- 跨云 Agent 实例互通
- 跨国 / 跨监管 Agent 协作

### 第 5 段 · ACP 的归宿 + 统一趋势 (5 分钟)

**IBM Agent Communication Protocol (2025-03, 已并入 A2A)**:
- IBM Research 随开源 BeeAI 平台发布的 Agent 通信协议
- REST 风格, 面向多框架 Agent 互操作 (任务级状态共享 / 多模态消息)
- 2025-08 宣布并入 Google A2A, 进入 Linux Foundation 治理; 独立仓库 i-am-bee/acp 已归档

> **译注**: ACP 的轨迹是这一代 Agent 协议快速整合的缩影: 2025-03 由 IBM Research 随 BeeAI 平台发布; 2025-06 Linux Foundation 成立 A2A 项目后, IBM 与 Google 于 2025-08 宣布 ACP 并入 A2A, 原仓库归档只读。本章保留其设计思想介绍 (多框架互操作、任务级状态共享), 但选型时不必再把它当作独立协议评估。

**OpenAI Agents SDK (2025-03-11)**:
- OpenAI 官方 Agent 开发框架, Swarm 的生产化继任
- 原生支持 MCP 工具, 紧跟 A2A
- Handoffs / Sessions / Guardrails / Tracing

**统一趋势**:
- **协议融合**: MCP + A2A + ANP → 单协议
- **Registry 标准化**: Agent Registry 类似 npm
- **全双工**: 双向流式 + 双向认证
- **多模态**: 文本 / 语音 / 视频统一

**2026 预测**:
- 单一 Agent 协议标准 (类似 LSP 之于 IDE)
- Agent Discovery (DNS-like)
- 跨厂商 Agent 协作生产化

## 四 · 协议对比矩阵

| 协议 | 厂商 | 时间 | 通信 | 加密 | 跨域 | 状态 |
|------|------|------|------|------|------|------|
| **MCP** | Anthropic | 2024-11 | JSON-RPC | TLS | 弱 | 标准化 |
| **A2A** | Google → Linux Foundation | 2025-04 | JSON-RPC / gRPC / REST (0.3) + SSE | OAuth2 | 弱 | 标准化 |
| **ANP** | 社区 (W3C CG) | 2024 发起 | HTTP + DID (did:wba) | 端到端 | 强 | 早期 |
| **Agents SDK** | OpenAI | 2025-03 | JSON-RPC | TLS | 弱 | 活跃 |

> ACP (IBM Research, 2025-03) 已于 2025-08 并入 A2A (Linux Foundation 治理), 不再单列。原 ACP 主打的多框架 Agent 互操作场景由 A2A 承接。

## 📌 本节要点

- **协议演进主线**: MCP (Anthropic 2024-11, 工具协议) → A2A (Google 2025-04, Agent 协作, 2025-06 起 Linux Foundation 治理) → ANP (2024 发起, 跨域互联)；IBM ACP (2025-03) 已于 2025-08 并入 A2A。每一层建立在上层之上，类比 HTTP → REST → GraphQL。
- **MCP 管的是"Agent ↔ 工具"**，A2A 管的是"Agent ↔ Agent"，ANP 管的是"跨域 Agent 网络"——三者互补而非竞争，选型先分清连接对象。
- **对比矩阵是选型入口**: 按"连接对象 / 发现机制 / 身份体系 / 传输层"四个维度对照，而不是按厂商站队。
- **部署建议**: 单机工具调用用 MCP 就够；跨团队/跨组织协作才需要 A2A；公网开放互联才考虑 ANP。
- **协议化是 LLM 工程化的最后一步**: 工具、协作、互联分层标准化后，Agent 系统才可能像 Web 服务一样组合与替换。
