# 第22章 · LLM Evaluation 方法学 · 单页 Proposal

## 一句话定位
> **Eval 是 LLM 的"度量衡"**: 没有好 Eval, 就没有 Reward Model / LLM-as-Judge / Harness / 可靠 RLHF。

## 为什么学这一章
- 2024 起 **Eval 已成为 LLM 工业的瓶颈** (saturated benchmarks / contamination)
- **Harness Engineering** 是新岗位 (Anthropic / OpenAI / DeepMind 均在招)
- 面试必考: **MMLU / HumanEval / LLM-as-Judge / Contamination**
- 不学 = "训练完了不知道模型好不好"

## 学什么 (8 节)
1. **为什么 Eval 是 LLM 的圣杯**
2. **传统 NLP 指标** (BLEU / ROUGE / METEOR / chrF / BERTScore)
3. **现代 Benchmark 体系** (MMLU / GSM8K / HumanEval / HELM / LiveBench)
4. **竞技场与人类偏好** (LMSYS Arena / Bradley-Terry / ELO)
5. **LLM-as-Judge** (Single-Point / Pairwise / Reference-based)
6. **Contamination 与 Benchmark 崩坏**
7. **Capability + Safety Eval 双轨**
8. **Harness Engineering 综述** (Eval / Inference / Agent / Safety / Data 5 大支柱)

## 学完后能做什么
- 选 **合适的 Benchmark 组合** 评估模型 (5-10 个, 覆盖能力/安全/对齐)
- 实现 **LLM-as-Judge** 评估 pipeline (含 bias 校准)
- 检测 **数据污染** 并构造 **私有 Hold-out**
- 搭建 **Eval Harness** (lm-evaluation-harness / OpenCompass)
- 在面试中讲清 **Bradley-Terry / ELO / LMSYS 排名原理**

## 5 大关键词
**Benchmark / LLM-as-Judge / Contamination / Harness / Bradley-Terry**
