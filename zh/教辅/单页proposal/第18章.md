## 选题 1: ML Feature Store 设计与实现

**TL;DR**: 用 Feast 实现统一 Feature Store, 在线 + 离线一致性, 离线训练 AUC +2%。

### 核心问题
- 在线 / 离线特征不一致 (training-serving skew)
- 特征重用低
- 跨团队难

### 目标
- Feast 部署
- 5 个特征
- 在线 < 10ms 延迟

### 关键公式
$$\text{Consistency} = 1 - \frac{|\text{online} - \text{offline}|}{|\text{offline}|}$$

### 创新点
- 增量特征
- 自动化漂移检测
- 跨语言 SDK

### 参考
- Feast (feast.dev)
- Tecton
- Hopsworks

## 选题 2: 实时推荐系统重构

**TL;DR**: 把 batch 推荐改为 real-time, 用 Kafka + Flink + 在线推理, 提升 CTR +5%。

### 核心问题
- 离线推荐延迟 1 小时
- 用户实时行为丢失
- CTR 上不去

### 目标
- 端到端 < 100ms
- Kafka + Flink + vLLM
- A/B test

### 关键公式
$$T_{\text{e2e}} = T_{\text{event}} + T_{\text{feature}} + T_{\text{infer}}$$

### 创新点
- 在线学习 (bandit)
- KV 复用
- 缓存

### 参考
- DoorDash 派单
- Uber Michelangelo
- Netflix 推荐

## 选题 3: 数据漂移检测与自动重训

**TL;DR**: 自动检测分布漂移 + 触发模型重训 + 灰度发布, 解决模型陈旧问题。

### 核心问题
- 模型上线后性能下降
- 数据分布漂移
- 手动监控困难

### 目标
- PSI / KS 自动检测
- 触发重训流水线
- 灰度发布

### 关键公式
$$PSI = \sum (P_{\text{new}} - P_{\text{ref}}) \ln \frac{P_{\text{new}}}{P_{\text{ref}}}$$

### 创新点
- 在线检测
- 自动 retrain
- 模型版本管理

### 参考
- Evidently AI
- WhyLabs
- Arize

## 选题 4: 数据湖 + Iceberg + ML

**TL;DR**: 在 Iceberg 数据湖上做 ML, 支持 schema 演进 + 时间旅行, 提升数据工程效率。

### 核心问题
- 数据 schema 变化灾难
- 训练 / 服务数据版本不一致
- 重算成本高

### 目标
- Iceberg + Spark
- 时间旅行
- ML 训练 + 推理同源

### 关键公式
$$T_{\text{retrain}} = \frac{N_{\text{features}} \times C_{\text{compute}}}{B_{\text{compute}}}$$

### 创新点
- 增量 ETL
- 物化视图
- Schema 演进

### 参考
- Apache Iceberg
- Delta Lake
- Apache Hudi

## 选题 5: 端云协同 ML 平台

**TL;DR**: 边缘 + 云协同 ML 平台, 简单模型在边缘, 复杂在云, 节省 50% 带宽 + 延迟。

### 核心问题
- 全部云端推理延迟大
- 全部边缘精度低
- 协同机制缺

### 目标
- 边缘小模型 (Llama 3 1B)
- 云端大模型 (Llama 3 70B)
- 路由决策

### 关键公式
$$T_{\text{total}} = \min(T_{\text{edge}}, T_{\text{cloud}} + T_{\text{network}})$$

### 创新点
- 难度分类器
- 缓存复用
- 自适应路由

### 参考
- 端云协同 (Cloud-Edge)
- Llama 3.2 1B/3B
- MobileLLM
