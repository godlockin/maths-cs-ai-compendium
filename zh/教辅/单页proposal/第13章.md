## 选题 1: GPU 共享内存中的 LLM 推理调度

**TL;DR**: 设计一个 GPU kernel 调度器, 让多个 LLM 请求 (不同长度) 在共享 GPU 上高效推理, 目标 GPU 利用率 90%+。

### 核心问题
- LLM 推理是 memory-bound (KV cache)
- 不同请求长度差异大
- 当前 vLLM / TGI 的 continuous batching 不完美

### 目标
- 改进调度策略 (优先级 + 长度自适应)
- 在 H100 上 A/B test
- GPU 利用率从 70% 提升到 90%+

### 关键公式
$$\text{Throughput} = \frac{N_{\text{tokens}}}{\text{Latency}_{\text{total}}}$$
$$\text{KV cache size} = 2 \cdot N_{\text{layers}} \cdot N_{\text{heads}} \cdot d_{\text{head}} \cdot N_{\text{tokens}}$$

### 创新点
- 长度感知的 chunked prefill
- 优先级调度 (SLO-aware)
- KV cache 压缩

### 参考
- vLLM, "Paged Attention", SOSP 2023
- TGI (Text Generation Inference)
- Flash Attention, NeurIPS 2022

## 选题 2: 异构 GPU 集群的分布式训练

**TL;DR**: 在 1024 节点 (H100 + A100 混合) 上训练 LLM, 优化通信成本。

### 核心问题
- 异构 GPU 网络带宽差异
- AllReduce 是瓶颈
- 节点故障容错

### 目标
- 异构感知的 collective (NCCL)
- 梯度压缩
- 节点故障 checkpoint

### 关键公式
$$T_{\text{step}} = T_{\text{compute}} + T_{\text{comm}}$$
$$T_{\text{AllReduce}} \propto \frac{N \cdot M}{B_{\text{network}}}$$

### 创新点
- 拓扑感知调度
- 异步梯度同步
- 弹性训练 (spot instances)

### 参考
- Megatron-LM (NVIDIA)
- DeepSpeed ZeRO
- PyTorch FSDP

## 选题 3: 操作系统对 LLM 推理的资源管理

**TL;DR**: 用 Linux cgroups / namespaces 给 LLM 服务分配 GPU, 避免多租户干扰。

### 核心问题
- 多个 LLM 服务共享 GPU 节点
- 当前 MIG (Multi-Instance GPU) 不灵活
- 推理延迟抖动

### 目标
- 自定义 GPU scheduler
- cgroups v2 集成
- A/B test 延迟抖动降低 50%

### 关键公式
$$\text{Jitter} = \text{std}(T_{\text{latency}})$$

### 创新点
- GPU 公平调度算法
- 显存 + 算力配额
- 与 Kubernetes 集成

### 参考
- NVIDIA MIG
- Kubernetes GPU device plugin
- NVIDIA k8s-device-plugin

## 选题 4: 内存墙 (Memory Wall) 对 GNN 训练的影响

**TL;DR**: 研究内存带宽如何限制 GNN 训练, 设计 cache-friendly 图存储格式。

### 核心问题
- GNN 训练中, 邻居加载占 80% 时间
- 当前 CSR/CSC 格式 cache 局部性差
- 大图 (OGB-ppa) 训练慢

### 目标
- cache-aware 图存储
- 预取策略
- 训练加速 2×

### 关键公式
$$T_{\text{mem}} = \frac{N_{\text{bytes}}}{B_{\text{mem}}}$$
$$B_{\text{mem}}^{\text{HBM}} \approx 3 \text{ TB/s (H100)}$$

### 创新点
- 双缓冲预取
- GPU 上的 tile-based 加载
- PyG / DGL 集成

### 参考
- Cluster-GCN
- GraphSAINT
- PyG 论文

## 选题 5: 编译器优化 LLM 内核 (Triton / TVM)

**TL;DR**: 用 Triton / TVM 自动调优 LLM 关键算子 (attention, GeLU), 性能优于手写 CUDA。

### 核心问题
- 手写 CUDA 优化 attention 耗时
- 不同 GPU 架构需要重写
- 自动化工具性能差

### 目标
- Triton 优化 attention kernel
- 与 Flash Attention 3 对比
- 5 个 GPU 架构自动调优

### 关键公式
$$\text{Speedup} = \frac{T_{\text{baseline}}}{T_{\text{optimized}}}$$

### 创新点
- 跨架构调优
- 算子融合
- 自动调度 (Ansor / Meta-Schedule)

### 参考
- Flash Attention 3
- Triton (OpenAI)
- TVM / Ansor

## 评估方法论共性

| 方法 | 公式 | 用法 |
|------|------|------|
| 加速比 | $\frac{T_{\text{baseline}}}{T_{\text{new}}}$ | 所有选题 |
| GPU 利用率 | $\frac{\text{Active SMs}}{\text{Total SMs}}$ | 选题 1, 2 |
| 内存带宽 | $\frac{N_{\text{bytes}}}{T_{\text{measured}}}$ | 选题 4 |
| 延迟抖动 | $\text{std}(T_{\text{latency}})$ | 选题 3 |
| 算子 speedup | $\frac{T_{\text{eager}}}{T_{\text{compiled}}}$ | 选题 5 |
