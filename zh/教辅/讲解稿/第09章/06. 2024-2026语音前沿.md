## 一 · 一句话总览

> **2024-2026 语音 AI = 4 大方向**: 语音克隆 (VALL-E 2 / AudioBox) + 音乐生成 (Suno v4 / Udio) + 实时对话 (GPT-4o / Moshi) + 多模态 (AudioBox / Stable Audio 2)。LLM 时代, 语音模型从"分立流水线"变成"统一端到端"。

---

## 二 · 心智模型

把 2024-2026 语音 AI 想成"四代演进":
- **第一代 (2017-2019)**: Tacotron 2 / WaveNet 三段流水线
- **第二代 (2020-2022)**: FastSpeech 2 / VITS / Diff-TTS 端到端
- **第三代 (2023-2024)**: VALL-E / Bark / AudioBox 多模态
- **第四代 (2024-2026)**: 实时对话 (GPT-4o voice) + 音乐生成 (Suno v4) + 长上下文

每一代都把"分段"减少, 推向"统一"。

## 三 · 章节主线 (5 段)

### 第 1 段 · VALL-E 2 与语音克隆 (10 分钟)

#### 3.1.1 VALL-E 2 (2024, Microsoft)

**零样本语音克隆**: 给 3 秒参考音频, 合成任意文本。

**架构**:
- **Codec** (Encodec): 音频 → 离散 token
- **LM**: 文本 + 提示 audio → 目标 audio tokens
- **Decoder**: tokens → 波形

**突破**:
- 说话人相似度 (SIM): 0.6+
- 词错误率 (WER): 0.5% (vs VALL-E 1.0)
- 数据: 60K 小时 (LibriLight)

**伦理风险**: 深度伪造 → Microsoft 限制使用。

#### 3.1.2 AudioBox (Meta 2023)

**统一音频生成**: 语音 + 音乐 + 音效一个模型。

**输入**:
- 文本提示
- 声音风格 (style)
- 参考音频

**关键技术**:
- AudioBox-VS: 语音克隆
- AudioBox-MM: 多模态
- AudioCraft 集成

#### 3.1.3 Seed-Music / Seed-TTS (字节跳动 2024)

**Seed-TTS**:
- 5 秒克隆
- 中文最自然
- 情感 / 韵律控制

**Seed-Music**:
- 歌词 + 风格 → 完整歌曲
- 60 秒
- 商用领先

#### 3.1.4 中文语音克隆

| 模型 | 公司 | 特点 |
|------|------|------|
| CosyVoice | 阿里 | 开源, SOTA |
| GPT-SoVITS | 开源 | 中文首选 |
| ChatTTS | 开源 | 情感丰富 |
| IndexTTS | 索引 | 商业可用 |
| F5-TTS | 上海交大 | 快速流式 |

### 第 2 段 · 实时语音对话 (8 分钟)

#### 3.2.1 GPT-4o Voice (OpenAI 2024-05)

**首原声多模态对话**:
- 平均响应 320ms (接近人类)
- 情感 + 语气 + 节奏
- 任意打断 ("讲笑话时叫停")

**架构**:
- 原生多模态 Transformer
- 音视频 + 文本统一
- 不再分 ASR + LLM + TTS

#### 3.2.2 Moshi (Kyutai 2024)

**实时语音对话** (法国 Kyutai):
- 200ms 延迟
- 流式双向语音
- 7B 参数
- 全开源

**创新**:
- Mimi codec (12 Hz)
- Inner Monologue (思考 + 说话并行)
- 模拟呼吸 / 叹气

#### 3.2.3 端到端语音模型

- **GLM-4-Voice** (智谱, 2024)
- **Step-Audio** (阶跃星辰, 2024)
- **Doubao Voice** (字节, 2024)
- **MiniMax-Voice** (MiniMax, 2024)

**共同特点**:
- 一体化 (ASR + LLM + TTS)
- 实时流式
- 中文领先

### 第 3 段 · 音乐生成 (10 分钟)

**6 秒 → 60 秒 + 完整歌曲**:

**优势**: 完全开源, 可商用

## 六 · 易错点 (5 条)

1. **VALL-E 2 ≠ 真智能**: 仅克隆风格, 不理解语义

## 十一 · 2026-11 审计增补: ASR/TTS 新快照 (讲解 12 分钟)

> 本节四块内容均取自正文 Ch09 §02/§03 的 2026-11 核实增补, 与前文 2024 快照是**代际对照**而非替换关系。

### 11.1 Open ASR Leaderboard 双口径: 换尺子, 不是模型退化

先讲一个方法论问题, 因为它比任何单个模型都重要。

HF Open ASR Leaderboard 在 2026-11 换了评测框架、把榜单整体重跑了一遍, 结果所有模型的 Avg. WER 绝对值整体上移。于是现在榜单有两套数字:

- **2026-10 快照 (旧框架)**: Whisper large-v3 Avg. WER 7.44%、RTFx 146; 榜首 Cohere transcribe-03-2026 5.42%、granite-4.0-1b-speech 5.52%、canary-qwen-2.5b 5.63%、Qwen3-ASR-1.7B 5.76%。
- **2026-11 新框架口径**: Whisper large-v3 变成 8.24%、RTFx 471; Cohere 6.72%、Qwen3-ASR-1.7B 6.15%、canary-qwen 6.92%、granite-4.0 7.69%。

学生最容易犯的错, 是拿 8.24% 减 7.44% 然后说"Whisper 退步了 0.8 个点"。**这两组数字不可直接相减**——尺子换了, 被测的物体没变。引用任何具体 WER, 都必须带上快照月份和评测框架版本。

新框架下还有两个看点。一是榜首区间进入 4-6% WER, 新入局者包括 NVIDIA Nemotron-3.5-Transcribe-30B-A4B (6.13%, 30B MoE)、IBM granite-speech-5.0-2b (6.68%)、Luciole-8B-Audio、FUTO asr4all 三档。二是速度天花板被推到 Parakeet-TDT-0.6B-v2 的 fast-gpu 档 RTFx 17254、asr4all-s 28913——对比 Whisper 的 471, 差了近两个数量级。结论和旧口径时代一样: Whisper large-v3 仍是语言覆盖与生态的金标准, 但"默认选 Whisper"在精度敏感和速度敏感场景都已不成立。

### 11.2 Qwen3-ASR: 中国大厂的开源通才 (2026-01)

阿里通义千问 2026-01-29 发布 (arXiv:2601.21337), 0.6B / 1.7B 两档, 官方称 1.7B 在开源 ASR 中达到 SOTA、可与最强商业 API 竞争。三个记忆点:

1. **30 种语言 + 22 种中国方言 = 52 种语言/方言**, 中文方言覆盖是它相对欧美模型的结构性长板;
2. **流式与离线同一个模型统一**, 还支持长音频——省掉了过去"流式一套、离线一套"的维护成本;
3. 配套 **Qwen3-ForcedAligner-0.6B** 做 11 种语言的强制对齐, 5 分钟内输出任意单位时间戳, 精度超过基于 E2E 的对齐方案。

它在两套口径下分别是 5.76% (2026-10) 和 6.15% (2026-11), 正好当双口径教学的活标本。

### 11.3 Fish Audio S2: 开源 TTS 从"能朗读"到"能对话" (2026-03)

Fish Audio S2 (2026-03-09, arXiv:2603.08823) 标志开源 TTS 从"单轮朗读"迈向"对话式可控"。前面讲过的 Kokoro、Orpheus、Dia 主打"把一段文本读好", 而 S2 原生面向**多说话人、多轮对话**生成, 用**自然语言描述做指令控制**——不是换音色, 而是按指令改情绪、改节奏。

工程上它同时开放三样东西: 模型权重、微调代码、基于 SGLang 的生产级流式推理引擎; 实测 **RTF 0.195**, 即合成耗时约为音频时长的五分之一。这是"开源 TTS 从玩具到可上线"的分水岭。

### 11.4 Fish Audio Drama 3: 35B MoE 的"导演式表演" (2026-10)

Drama 3 (2026-10-13, arXiv:2610.18010) 是这条线的最新一代, 把文本变成**"有导演的表演"** (directed performance)。骨干是 **35B 参数 MoE, 每个 token 只激活 3B**——总规模吃 LLM 缩放红利, 单 token 成本保持可控。

它把四件过去要分开做的事收进同一个模型: 多轮修订 (下一轮给意见就改稿)、场景配音 (多角色对戏)、按 infilling 编辑已有语音、流式文本输入。这是"编解码语言模型吃 LLM 缩放红利"路线的最新证据: 对照第八节的两大范式, Drama 3 用 MoE 把编解码 LM 的表达力和流式生成的可控性装进了一个模型。

### 11.5 一句话收口

2026 年的语音前沿, ASR 侧是**榜单换框架 + 榜首 4-6% WER + 速度两个数量级分化**, TTS 侧是**从朗读到导演、从单轮到多轮对话**; 记口径比记数字重要, 记方法比记型号重要。
