## 一 · 案例 1: SWE-Agent 实战 (2024-2025)

### 1.1 任务

**GitHub Issue 自动修复**:
- 输入: GitHub Issue 描述
- 输出: 自动生成的代码 Patch
- 评估: SWE-bench 验证

### 1.2 实现

```python
# 1. 安装 swagent
pip install swebench

# 2. 启动
from swebench import SWEAgent

agent = SWEAgent(
    model="claude-3.5-sonnet",
    harness="langgraph",
    tools=["bash", "read_file", "write_file", "search"],
)

# 3. 处理 issue
result = agent.run(
    issue_id="pytest-dev__pytest-1234",
    repo_path="./repos/pytest",
)
print(f"Patch: {result.patch}")
```

### 1.3 性能

| Agent | Pass@1 |
|-------|--------|
| Claude 3.5 Sonnet + LangGraph | 49% |
| GPT-4o + AutoGen | 38% |
| Cursor Composer | 70%+ |
| Devin 2 | 65% |

### 1.4 关键洞察

- **多 Agent 协作 > 单 Agent**: 性能 +20%
- **显式 DAG > 对话式**: 稳定性 +30%
- **工具越简单越好**: 复杂工具反而拖慢

## 二 · 案例 2: Agentless 极简方案 (2024 IBM)

### 2.1 核心理念

**不用 Agent, 3 步流程**:
1. **定位** (Localization): LLM 找到需要修改的文件
2. **修复** (Patching): LLM 生成 patch
3. **验证** (Validation): 跑测试

### 2.2 实现

```python
# Agentless 3 步
from agentless import locate, patch, validate

# 1. 定位
locs = locate(issue, repo_path)  # 找到关联文件

# 2. 修复
patch = patch(issue, locs)  # 生成 patch

# 3. 验证
result = validate(patch, test_cases)
```

### 2.3 性能

| 指标 | Agentless | SWE-Agent |
|------|-----------|-----------|
| Pass@1 | 48% | 49% |
| 速度 | 5× | 1× |
| 稳定性 | 高 | 中 |

### 2.4 关键洞察

**简单胜过复杂**: 显式 3 步胜过复杂对话循环。

## 三 · 案例 3: LLM-as-Judge 评测 (2024-2025)

### 3.1 任务

**GPT-4 评估 GPT-4 输出**:
- 与人类评分相关性 85%+
- 成本降低 100×

### 3.2 实现

```python
from langchain.evaluation import LLMChainEvaluator

judge = LLMChainEvaluator(
    model="gpt-4-turbo",
    criteria="correctness",
    rubric_prompt="...",
)

# 评估
result = judge.evaluate_strings(
    input="What is the capital of France?",
    prediction="Paris",
    reference="Paris",
)
print(f"Score: {result['score']}")  # 0.95
```

### 3.3 风险与防御

- **位置偏置**: LLM 倾向选择第 1 个
- **长度偏置**: LLM 倾向长答案
- **自我偏置**: LLM 倾向自己风格

**防御**:
- 随机化位置
- 校准权重
- 多 LLM 集成

### 3.4 关键洞察

**LLM-as-Judge 够用但需校准**: 与人类 85%+ 相关性。

## 四 · 案例 4: RAG 生产实施 (2024-2025)

### 4.1 任务

**企业知识库 + LLM 问答**:
- 输入: 100 万份文档
- 输出: 实时回答 (5 秒内)

### 4.2 架构

```
文档 → 分块 (512-1024 tokens) → Embedding → 向量库
                                            ↓
用户 Query → Embedding → 检索 Top-K → LLM 生成
```

### 4.3 关键决策

| 维度 | 选择 | 理由 |
|------|------|------|
| **Embedding** | BGE-M3 / Qwen3-Embed | 中文 SOTA |
| **向量库** | Milvus / Qdrant | 分布式 |
| **分块** | 512 tokens + overlap | 平衡 |
| **检索** | hybrid (BM25 + vector) | 召回率 |
| **Re-ranking** | BGE-Reranker | 准确性 |
| **LLM** | Qwen 2.5 / DeepSeek | 中文 |

### 4.4 实现

```python
from langchain.retrievers import HybridRetriever
from langchain.embeddings import BGEEmbeddings

# 1. 混合检索
retriever = HybridRetriever(
    bm25_index="./bm25",
    vector_index=MilvusCollection("./docs"),
    embeddings=BGEEmbeddings(),
    reranker=BGEReranker(),
)

# 2. RAG Chain
chain = RetrievalQA.from_chain_type(
    llm=ChatTongyi(model="qwen-max"),
    retriever=retriever,
    chain_type="stuff",
)

# 3. 查询
result = chain.run("公司年营收是多少？")
```

### 4.5 关键洞察

- **Hybrid 检索 > 单一**: 召回率 +20%
- **Re-ranking 关键**: 准确率 +30%
- **元数据过滤**: 提升 50%

## 五 · 案例 5: RAG 高级模式 (5 种, 2024-2026)

### 5.1 Self-RAG

```python
# Self-RAG: 模型判断何时需要检索
chain = SelfRAGChain(
    model="qwen-72b",
    threshold=0.7,
    # 自动决定是否检索
)
```

### 5.2 CRAG (Corrective RAG)

```python
# 检索结果评估 + 修正
chain = CRAGChain(
    grader_model="gpt-4o-mini",
    web_search_fallback=True,  # 检索差时启动 web 搜索
)
```

### 5.3 Adaptive RAG

```python
# 智能选择检索源
chain = AdaptiveRAGChain(
    query_analyzer="small-llm",
    retrieval_strategies=["vector", "bm25", "sql", "api"],
)
```

### 5.4 Agentic RAG

```python
# 多 Agent 协作 RAG
chain = AgenticRAG(
    agents=[
        QueryAnalyzerAgent(),
        RetrievalAgent(),
        RerankingAgent(),
        GenerationAgent(),
    ],
)
```

### 5.5 Graph RAG (Microsoft 2024)

```python
# 把文档建成图, 用图遍历回答
chain = GraphRAG(
    graph_index="./graph",
    traversal="ppr",
)
```

### 5.6 性能对比

| 模式 | 准确率 | 延迟 | 成本 |
|------|--------|------|------|
| Vanilla RAG | 0.70 | 1s | 1× |
| HyDE | 0.75 | 2s | 1.5× |
| Self-RAG | 0.80 | 3s | 2× |
| CRAG | 0.82 | 4s | 3× |
| Adaptive | 0.85 | 5s | 4× |
| Graph RAG | 0.88 | 8s | 10× |

## 六 · 扩展: 5 类实战场景

### 6.1 端到端训练项目

**项目 1: 客服 LLM**
- 数据: 100 万条对话
- 模型: Qwen 2.5 7B + LoRA
- 训练: 3 小时 × 4 GPU
- 部署: vLLM + Chat UI

**项目 2: 文档问答**
- 文档: 5000 份 PDF
- 检索: BGE + Milvus
- LLM: GPT-4o
- 性能: 90% 准确率

**项目 3: 代码助手**
- 模型: CodeLlama 70B
- 微调: LoRA r=16
- 推理: vLLM 0.7
- 速度: 100 tokens/sec

**项目 4: 视频摘要**
- 视频: 1000 段
- 视觉: InternVL2
- 摘要: GPT-4o
- 输出: 30 秒摘要

**项目 5: 蛋白质-文本检索**
- 蛋白: PDB 数据库
- 文本: PubMed
- 检索: AlphaFold 3 + RAG
- 输出: 蛋白功能解释

### 6.2 面试 5 大题

**题 1: SWE-bench 怎么评估?**
- 答: 自动跑测试, Pass@1 验证

**题 2: RAG 与 Long Context 区别?**
- 答: RAG 检索 / Long Context 注入

**题 3: GRPO vs PPO?**
- 答: 免 critic, 组内归一化

**题 4: Flash Attention 优化点?**
- 答: 分块 + 重计算 + WGMMA

**题 5: RAG 评估指标?**
- 答: 召回率 + 准确率 + 延迟
