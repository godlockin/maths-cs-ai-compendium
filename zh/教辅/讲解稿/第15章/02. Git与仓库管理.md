## 二 · 章节主线 (5 段)

### 第 1 段 · Git 基础 (8 分钟)

#### 3.1.1 三状态

```
工作区 → (git add) → 暂存区 → (git commit) → 本地仓库 → (git push) → 远程仓库
```

#### 3.1.2 初始化与克隆

```bash
git init                          # 新仓库
git clone https://github.com/x/y  # 克隆
git config --global user.name "Name"
git config --global user.email "a@b.com"
```

#### 3.1.3 基本命令

```bash
git status                        # 状态
git add file.py                   # 加暂存
git add .                         # 全部
git commit -m "feat: add ..."     # 提交
git commit --amend                # 改最近 commit
git log --oneline -20             # 看历史
git diff                          # 工作区 vs 暂存
git diff --staged                 # 暂存 vs 仓库
```

#### 3.1.4 远程仓库

```bash
git remote -v                     # 看远程
git remote add origin <url>       # 加远程
git push -u origin main           # 首次推送
git pull                          # 拉取 + 合并
git fetch                         # 只拉取, 不合并
```

### 第 2 段 · 分支管理 (10 分钟)

#### 3.2.1 分支操作

```bash
git branch                        # 列出本地
git branch -a                     # 含远程
git checkout -b feature/x         # 创建并切换
git checkout main                 # 切回
git branch -d feature/x           # 删除 (已合并)
git branch -D feature/x           # 强删 (未合并)
```

#### 3.2.2 merge 与 rebase

**merge**: 保留分支结构, 生成 merge commit。

```bash
git checkout feature/x
git merge main                    # 把 main 合到 feature/x
```

**rebase**: 把 commit 重放到目标分支, 历史线性。

```bash
git checkout feature/x
git rebase main                   # 重放 commit
```

**比较**:

| 维度 | merge | rebase |
|------|-------|--------|
| 历史 | 分支结构 | 线性 |
| commit 数 | +1 merge commit | 不变 |
| 冲突解决 | 一次性 | 每个 commit |
| 适用 | 公共分支 | 个人分支 |

**黄金法则**: 推送前 rebase, 推送后 merge。

#### 3.2.3 冲突解决

```bash
git pull                          # 自动 merge
# 冲突文件
<<<<<<< HEAD
你的代码
=======
队友的代码
>>>>>>> branch
# 手动编辑
git add .
git commit                       # 解决冲突后 commit
```

#### 3.2.4 交互式 rebase

```bash
git rebase -i HEAD~3              # 编辑最近 3 个 commit
```

编辑器中:
- `pick`: 保留
- `reword`: 改 message
- `squash`: 合并到前一个
- `drop`: 删除

#### 3.2.5 stash

暂存未提交修改:

```bash
git stash                         # 暂存
git stash pop                     # 恢复
git stash list                    # 列表
git stash apply stash@{0}         # 恢复指定
```

### 第 3 段 · 协作: PR / Code Review (8 分钟)

#### 3.3.1 Pull Request 流程

1. Fork / 切分支
2. 写代码 + commit
3. push 到远端
4. 开 PR (描述变更)
5. Review → 修改 → merge
6. 删分支

#### 3.3.2 Code Review 要点

- 正确性: bug, 边界
- 可读性: 命名, 注释
- 性能: 算法, IO
- 风格: linter / formatter
- 测试: 覆盖, 边界

#### 3.3.3 提交规范 (Conventional Commits)

```
<type>(<scope>): <subject>

<body>

<footer>
```

类型: feat / fix / docs / style / refactor / test / chore。

例: `feat(auth): add OAuth login`。

工具: `commitlint`, `standard-version`。

### 第 4 段 · 高级 Git (8 分钟)

#### 3.4.1 cherry-pick

挑单个 commit 应用:

```bash
git cherry-pick <commit-sha>
```

#### 3.4.2 submodule

嵌入子仓库:

```bash
git submodule add <url> path/
git submodule update --init --recursive
```

#### 3.4.3 Git LFS

大文件存储:

```bash
git lfs install
git lfs track "*.pt"              # 跟踪模型权重
git add .gitattributes
```

#### 3.4.4 worktree

多工作目录:

```bash
git worktree add ../wt-bugfix -b bugfix
```

#### 3.4.5 reflog

恢复误删:

```bash
git reflog                        # HEAD 历史
git checkout -b recovered <sha>   # 找回 commit
```

### 第 5 段 · 实战与陷阱 (8 分钟)

#### 3.5.1 仓库结构

```
project/
├── .git/
├── .gitignore          # 忽略文件
├── README.md
├── src/
├── tests/
├── docs/
└── data/               # 通常 .gitignore
```

#### 3.5.2 .gitignore 模板

Python:
```
__pycache__/
*.pyc
.pytest_cache/
.env
*.egg-info/
dist/
build/
```

#### 3.5.3 Git LFS 用于 AI

```bash
# 跟踪大文件
git lfs track "*.pt"
git lfs track "*.bin"
git lfs track "data/*"
```

避免 git 仓库膨胀。

#### 3.5.4 常见陷阱

1. **commit 敏感信息**: 用 BFG / git-filter-repo 清理。
2. **大文件 push**: 用 LFS 或外部存储 (S3)。
3. **force push**: 慎用, 可能覆盖队友。
4. **submodule 嵌套**: 复杂, 考虑 monorepo。
5. **分支命名**: 用前缀 `feature/`, `bugfix/`, `release/`。

#### 3.5.5 Git 平台

| 平台 | 特点 |
|------|------|
| **GitHub** | 主流, Actions, Copilot |
| **GitLab** | 自托管, CI 强大 |
| **Bitbucket** | Atlassian 集成 |
| **Gitee** | 国内 |

## 三 · 易错点 (5 条)

1. **merge vs rebase**: 已推送的分支别 rebase。
2. **commit --amend**: 已推送别 amend。
3. **force push**: 慎用, 通知队友。
4. **大文件**: 用 LFS, 别直接 add。
5. **git stash pop**: 可能有冲突, 检查。
