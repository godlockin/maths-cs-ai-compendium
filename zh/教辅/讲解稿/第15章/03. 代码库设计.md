#### 3.1.1 Python 包结构

```
my_ai_project/
├── pyproject.toml          # 依赖 + 元数据
├── README.md
├── src/
│   └── mypkg/

```

#### 3.1.2 src layout 优势

- 避免 import 混乱
- 强制包路径, 利于测试
- 业界标准

#### 3.1.3 依赖管理

| 工具 | 特点 |
|------|------|
| **pip + requirements.txt** | 简单 |
| **poetry** | 依赖 + 打包 + lock |
| **uv** | 快 (10× pip) |
| **conda** | 适合 ML + GPU |
| **pip-tools** | 编译 requirements |

#### 3.1.4 配置管理

```python
# 用 Pydantic

class TrainConfig(BaseModel):
    lr: float = 1e-3
    batch_size: int = 32
    epochs: int = 10

```

优于 hard-code 或 argparse。

### 第 2 段 · API 设计 (10 分钟)

#### 3.2.1 REST API

资源导向, HTTP 方法:

| 方法 | 用途 | 例 |
|------|------|-----|
| GET | 读 | `GET /users/1` |
| POST | 创建 | `POST /users` |
| PUT | 全量更新 | `PUT /users/1` |
| PATCH | 部分更新 | `PATCH /users/1` |
| DELETE | 删除 | `DELETE /users/1` |

#### 3.2.2 REST 状态码

| 码 | 含义 |
|----|------|
| 200 | OK |
| 201 | Created |
| 400 | Bad Request |
| 401 | Unauthorized |
| 404 | Not Found |
| 500 | Server Error |

#### 3.2.3 FastAPI 示例

```python
from fastapi import FastAPI, HTTPException
from pydantic import BaseModel

app = FastAPI()

class User(BaseModel):
    name: str
    email: str

users = {}

@app.post("/users", status_code=201)
async def create_user(user: User):
    users[user.email] = user
    return user

@app.get("/users/{email}")
async def get_user(email: str):
    if email not in users:
        raise HTTPException(404, "User not found")
    return users[email]
```

自动生成 OpenAPI 文档 (`/docs`)。

#### 3.2.4 GraphQL

客户端定字段, 一次查询拿全部。

```graphql
query {
  user(id: 1) {
    name
    posts {
      title
    }
  }
}
```

适用: 多端, 字段多变。

#### 3.2.5 gRPC

Protobuf + HTTP/2, 强类型, 流式。

```protobuf
service LLMService {
  rpc Generate (GenerateRequest) returns (GenerateResponse);
  rpc Stream (StreamRequest) returns (stream StreamResponse);
}
```

适用: 微服务内部通信。

### 第 3 段 · SOLID 与设计模式 (10 分钟)

#### 3.3.1 SOLID 五原则

| 原则 | 含义 | 例子 |
|------|------|------|
| **S**ingle Responsibility | 一个类一个职责 | `UserRepository` 只管用户数据 |
| **O**pen/Closed | 扩展开放, 修改关闭 | 通过继承扩展功能 |
| **L**iskov Substitution | 子类可替换父类 | `Square extends Rectangle` |
| **I**nterface Segregation | 接口要小 | 拆分大接口 |
| **D**ependency Inversion | 依赖抽象, 不依赖具体 | DI 容器 |

#### 3.3.2 常用模式

**工厂 (Factory)**:

```python
class ModelFactory:
    @staticmethod
    def create(name: str):
        if name == "gpt":
            return GPTModel()
        elif name == "llama":
            return LlamaModel()
        raise ValueError(name)
```

**单例 (Singleton)**:

```python
class Config:
    _instance = None
    def __new__(cls):
        if cls._instance is None:
            cls._instance = super().__new__(cls)
        return cls._instance
```

**策略 (Strategy)**:

```python
class LossStrategy:
    def compute(self, pred, target): ...

class MSELoss(LossStrategy):
    def compute(self, p, t):
        return ((p - t) ** 2).mean()

# 运行时切换
loss_fn = MSELoss() if task == "regression" else CrossEntropyLoss()
```

**装饰器 (Decorator)**:

```python
import functools
import time

def timer(func):
    @functools.wraps(func)
    def wrapper(*args, **kwargs):
        t0 = time.time()
        result = func(*args, **kwargs)
        print(f"{func.__name__} took {time.time()-t0:.4f}s")
        return result
    return wrapper

@timer
def train():
    ...
```

**依赖注入 (DI)**:

```python
class Trainer:
    def __init__(self, model, optimizer, scheduler):
        self.model = model
        self.opt = optimizer
        self.sched = scheduler
```

依赖由外部传入, 便于测试和替换。

#### 3.3.3 反模式

- **God Object**: 一个类做所有事
- **Spaghetti Code**: 逻辑混乱
- **Magic Number**: 硬编码
- **Premature Optimization**: 过早优化

#### 3.4.4 ADR (Architecture Decision Records)

```markdown
# ADR-001: 选择 vLLM 作为推理引擎

## 状态
已采纳 (2026-01-15)

## 背景
LLM 推理服务需要高吞吐, 低延迟。

## 决策
采用 vLLM, 因其 PagedAttention 节省显存 4×。

## 后果
- 优点: 吞吐 +24×
- 缺点: 学习曲线
- 风险: 项目活跃度依赖 Berkeley
```

## 三 · 易错点 (5 条)

1. **全局变量**: 难测试, 用依赖注入。
2. **混合关注点**: 数据加载与训练混在一起, 难复用。
3. **缺文档**: 一个月后自己看不懂。
4. **硬编码路径**: 用配置。
5. **过度工程**: 小项目别用微服务。
