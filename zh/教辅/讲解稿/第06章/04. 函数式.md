## 导语（约 80 秒）

先抛一个数字。

PyTorch 2.0 团队 2022 年公开一组数据：在 84 个常见深度学习模型里, **torch.compile 加速比从 1.4× 到 2.7× 不等**——中位数 1.6×。免费的 1.6×。不换算法, 不改模型, 只换一个装饰器 `@torch.compile`。

背后原理是**计算图重写 (graph rewriting) + 自动求导**。但你写神经网络时, 不需要手写求导——你写 `loss.backward()`, 一切全自动。

这种"**写前向, 不写反向**"的范式, 就是今天的核心: **函数式编程视角下的 PyTorch**。PyTorch 之所以用 Python 而不是 C++, 不是因为 Python 算得快, 而是因为 Python 是**动态函数式语言**, 你可以把 `if/while/for` 嵌进 forward 里, PyTorch 都能跟踪。Ch06 §03 学的 MLP 之所以能用 PyTorch 一行 forward, 不是因为简单, 是因为 PyTorch 的"自动微分 + 动态图"恰好匹配函数式思维。

今天我们用 17 分钟讲清 4 件事: ① 函数式 vs 命令式编程的区别; ② PyTorch 的 `Tensor + autograd` 工作机制; ③ 装饰器 `torch.compile` 是什么; ④ 函数式在强化学习策略梯度里的体现 (与 Ch05 概率论+Ch06 §02 GD 的承上启下)。

## 核心概念一 · 命令式 vs 函数式（约 2.5 分钟）

**直觉。** 命令式编程像菜谱: "先打蛋, 再加盐, 再炒"。函数式像数学: "蛋 + 盐 → 炒蛋"。PyTorch 走的是第二条路。

**定义。**
- **命令式 (imperative)**: 一行一行执行, 变量随时可变。代表: Python 普通代码, NumPy。
- **函数式 (functional)**: 表达式 = 输入到输出的纯函数, 没有副作用。代表: Haskell, SQL, 数学公式 $f(x)$。

**例子。** 算 `(x + y) * z`:

```python
# 命令式
a = x + y
result = a * z

# 函数式
result = mul(add(x, y), z)  # 表达式树, 没有 a 这个变量
```

**关键差别**: 命令式有"中间变量 a"——可被外部修改; 函数式只有表达式, 不可修改。**PyTorch 的 tensor 操作介于两者之间**: 你写 `c = a + b`, 这是命令式; 但 PyTorch **悄悄记录了 "c = a + b" 这条边, 用作反向传播**——这是函数式。

**反例。** 试图在 PyTorch 中**就地修改叶子节点**会破坏计算图:
```python
x = torch.tensor([2.0], requires_grad=True)
x = x + 1  # 这创建了新 tensor, x 不再是叶子节点
# 应该写 x.add_(1) 才是原地
```
**一句话总结。** PyTorch 是**命令式语法 + 函数式自动微分**的混合体——你写 Python, 框架建计算图。

## 核心概念二 · Tensor 与 autograd（约 3.5 分钟）

**直觉。** 你写 `y = x ** 2 + 3 * x`, PyTorch 不只算 y 的值, 还**记录**这个表达式长什么样, 等你 `y.backward()` 时倒着推 $\partial y / \partial x$。

**定义。**
- **Tensor**: 多维数组, 类似于 NumPy ndarray, 多了 (1) GPU 加速能力, (2) 自动求导能力。
- **autograd (automatic gradient)**: 自动构建计算图 (DAG), 通过链式法则 (Ch03 §04) 反向传播求梯度。
- **计算图 (computation graph)**: 节点是 tensor, 边是运算 ("+", "*", "exp" 等), 从叶子 (输入) 到根 (loss) 的有向无环图。

**例子。** 算 $f(x) = x^2 + 3x$ 在 $x=2$ 的导数:
```python
x = torch.tensor([2.0], requires_grad=True)
y = x ** 2 + 3 * x
y.backward()
print(x.grad)  # tensor([7.])  ← 2x+3 在 x=2 = 7
```
**手动**: $f'(x)=2x+3$, $f'(2)=7$ ✓。autograd 用 Ch03 链式法则自动求, 无需手算。

**反例。** 试图在 autograd 跟踪的 tensor 上调 `+=` 或 `.item()` 后再 `backward`:
```python
x = torch.tensor([2.0], requires_grad=True)
y = x ** 2
y = y.detach() + 1  # detach() 把 y 拉出图外, 后续求导不到 x
y.backward()  # x.grad 仍为 0
```
**一句话总结。** `requires_grad=True` 进入 autograd 图, 任何在图内的运算会被记录, `backward()` 倒着走图算梯度。

## 核心概念三 · `torch.compile` 装饰器（约 2.5 分钟）

**直觉。** 你写 Python, Python 是解释执行 (一行一行解释), 慢。`torch.compile` 把 Python 翻译成**优化的 C++/CUDA 图**, 然后整图执行, 跳过 Python 解释器。

**定义。** `torch.compile(model, mode="reduce-overhead")` 通过 **TorchDynamo** 提取 Python 字节码中的 FX 图, 通过 **AOTAutograd** 提前生成反向传播, 通过 **Inductor** 生成融合算子的 CUDA kernel。**模式**: `default` (平衡) / `reduce-overhead` (CPU 开销) / `max-autotune` (慢编译换最快运行)。

**例子。** ResNet-50 训练一个 epoch:
```python
model = torchvision.models.resnet50()
model = torch.compile(model)  # 一行, 免费 1.4-2.7× 加速
for x, y in dataloader:
    loss = model(x).log_softmax(-1).gather(1, y).neg().mean()
    loss.backward()
```
**性能**: PyTorch 官方数据, BERT-base 推理加速 1.5×, ResNet-50 推理 1.6×, 训练 1.3×。

**反例。** 期待 `torch.compile` 解决一切慢: 数据加载瓶颈, GPU 通信瓶颈, 算子本身已是 fused——这些不在其优化范围。

**一句话总结。** `torch.compile` 把动态图**静态化 + 算子融合 + 自动调优**, 适合 GPU-bound 而非 Python-bound 的瓶颈。

## 核心概念四 · 函数式在策略梯度的体现（约 3 分钟）

**直觉。** Ch06 §02 GD 讲了"求梯度 → 下降"; 强化学习 (Ch06 §05 预告) 里的 **策略梯度 (Policy Gradient)** 思想完全函数式: 期望回报 $J(\theta)=E_{\tau\sim\pi_\theta}[R(\tau)]$, 求 $\nabla J$ 直接对期望求导。

**定义。** REINFORCE 算法 (Williams 1992):
$$\nabla_\theta J(\theta) = E_{\tau\sim\pi_\theta}\left[\sum_t R_t \nabla_\theta \log \pi_\theta(a_t\mid s_t)\right]$$
- 整条轨迹 $\tau$ 是一次函数式求值 $\pi_\theta$ 的产物。
- $\log\pi_\theta$ 是函数式的"对数概率"输出, 梯度 $\nabla\log$ 是函数式自动微分的副产物。
- 期望用蒙特卡洛 (Ch04 §05 复述) 估计, 每条轨迹 $\tau_i$ 给出 $\nabla\log\pi_\theta$ 的无偏估计。

**例子。** 倒立摆 (cartpole) 训练:
```python
def policy(state):  # 输入 state, 输出动作概率
    return torch.softmax(net(state), dim=-1)

for episode in range(1000):
    states, actions, rewards = [], [], []
    for t in range(200):
        p = policy(state)
        action = torch.multinomial(p, 1)
        new_state, r, done = env.step(action)
        states.append(state); actions.append(action); rewards.append(r)
        if done: break
    G = sum(rewards)  # 折扣回报 (Ch06 §05 详)
    for t in range(len(states)):
        loss = -G * torch.log(policy(states[t])[actions[t]])  # 策略梯度
        loss.backward()  # autograd 自动算 ∇log
        optimizer.step()
```
**关键**: 这段代码**完全没有手写梯度**——全部依赖 autograd。函数式范式: 写期望 → 写对数概率 → autograd 自动给出梯度。

**反例。** 试图在策略梯度代码里**手动算 $\nabla\log\pi$**: 复杂分布 (高斯, Beta) 下极其痛苦, 还容易算错。

**一句话总结。** 策略梯度 = 期望 + 对数似然 + autograd, 是函数式范式在 RL 中的极致体现。

## 一个走完全程的例子 · 简单线性回归从手写到函数式（约 2.5 分钟）

**场景**: 拟合 $y = 2x + 1 + \text{noise}$, 用 MSE 损失 (Ch06 §01)。

**版本 1 · 命令式手写梯度** (Ch06 §02 风格):
```python
x = torch.linspace(0, 10, 100)
y = 2 * x + 1 + torch.randn(100) * 0.1
w = torch.tensor([0.0], requires_grad=True)
b = torch.tensor([0.0], requires_grad=True)
lr = 0.01
for epoch in range(1000):
    y_pred = w * x + b
    loss = ((y - y_pred) ** 2).mean()
    grad_w = -2 * (x * (y - y_pred)).mean()  # 手写
    grad_b = -2 * (y - y_pred).mean()           # 手写
    w.data -= lr * grad_w
    b.data -= lr * grad_b
print(w.item(), b.item())  # ~2.0, ~1.0
```
**问题**: 手写 `grad_w` / `grad_b` 公式, 改损失函数要重算。

**版本 2 · 函数式 autograd** (本节风格):
```python
x = torch.linspace(0, 10, 100)
y = 2 * x + 1 + torch.randn(100) * 0.1
w = torch.tensor([0.0], requires_grad=True)
b = torch.tensor([0.0], requires_grad=True)
opt = torch.optim.SGD([w, b], lr=0.01)
for epoch in range(1000):
    y_pred = w * x + b
    loss = ((y - y_pred) ** 2).mean()  # autograd 自动求 ∇
    opt.zero_grad()
    loss.backward()  # 一步
    opt.step()
print(w.item(), b.item())  # ~2.0, ~1.0
```
**好处**: 改损失函数 (如换成 MAE 或 Huber) **不需重写梯度**——autograd 重新构建计算图, 一切自动。**注意**: Ch06 §02 我们学的是"手动求 $\nabla$", Ch06 §03 学的"链式法则"是 autograd 的数学基础; **本节函数式** 是工程封装: 写 forward, 自动 backward。

**Ch03 §04 → Ch06 §03 → Ch06 §04** 完整链路: 链式法则 (Ch03 数学) → 反向传播算法 (Ch03 → Ch06 §03) → autograd 工程实现 (本节)。

## 易错点回头看（约 80 秒）

1. **很多人以为** `requires_grad=True` 才有梯度计算——其实**叶子节点**才需要, 中间变量会自动追踪。
2. **很多人忘了** `optimizer.zero_grad()`, 导致梯度累积 (上一轮的梯度没清, 加上这一轮)。
3. **很多人以为** `torch.compile` 一定能加速——瓶颈在数据加载/IO 时, 编译优化无效果。
