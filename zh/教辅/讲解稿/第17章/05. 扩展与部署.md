## 三 · 推理部署架构

### 3.1 单模型小流量

```
用户 → Load Balancer → vLLM (1 GPU)
```

### 3.2 大模型 + 高流量

```
用户 → CDN/Edge
       → API Gateway (限流 / 认证)
       → 推理集群 (多个 vLLM Pod)
            ├─ Pod 1 (TP=4, 70B)
            ├─ Pod 2 (TP=4, 70B)
            └─ Pod 3 (TP=4, 70B)
       → 监控 (Prometheus + Grafana)
```

### 3.3 多模型 + 多区域

```
                    Global Load Balancer
                   /         |          \
            US-East      EU-West      Asia-Pacific
           (vLLM)        (vLLM)        (vLLM)
            70B           70B           70B
```

## 六 · 弹性伸缩

### 6.1 KEDA + K8s HPA

**KEDA** (Kubernetes Event-Driven Autoscaling):
- 基于 GPU 利用率 / 队列长度 / 延迟
- 弹性扩缩容到 0

```yaml
apiVersion: keda.sh/v1alpha1
kind: ScaledObject
metadata:
  name: llm-scaler
spec:
  scaleTargetRef:
    name: vllm-deployment
  triggers:
  - type: prometheus
    metadata:
      serverAddress: http://prometheus:9090
      query: rate(http_requests_total[1m])
      threshold: "100"
```

### 6.2 预测性扩容

- 基于历史 + 时间序列预测
- 提前扩容应对流量峰值
- 节省冷启动延迟

## 七 · 成本优化

### 7.1 成本维度

| 维度 | 优化方法 |
|------|----------|
| **GPU 成本** | Spot 实例 / 自研 NPU |
| **能耗** | 模型量化 / 蒸馏 |
| **请求数** | 缓存 / 批量 |
| **模型大小** | MoE / 蒸馏 |
| **延迟** | 调度 / 区域 |

### 7.2 Spot 实例 + 预emption 处理

```
AWS Spot 价格: $0.5-1.5/hr (vs On-demand $3-4/hr)
节省 50-70%
风险: 2 分钟通知回收
处理: 多 AZ 冗余 + 快速重启
```

### 7.3 模型路由 (按成本)

```
简单 query → Llama 3 8B ($0.05/1M token)
复杂 query → GPT-4 ($5/1M token)
代码 query → DeepSeek-Coder ($0.3/1M token)
```

## 八 · 容灾与多区域

### 8.1 主动-主动 (Active-Active)

- 多区域同时服务
- Anycast IP / DNS Geo-routing
- 区域故障 0 中断

### 8.2 主动-被动 (Active-Passive)

- 主区域 + 备区域
- 故障时切备 (5-30 分钟)
- 成本低

### 8.3 数据同步

- 模型权重跨区域同步 (S3 Cross-Region Replication)
- 配置 (ConfigMap) 全局一致
- KV cache 不跨区域
