## 一 · 一句话总览

> **Loop Engineering = 5 大循环模式 + 9 类失败检测 + 闭环设计原则**。任何"重复执行"系统都需要 loop engineering: **OS Loop (调度) / RL Loop (强化) / Agent Loop (LLM) / DevOps Loop (CI/CD) / Control Loop (反馈)**。修好"缰绳"才能让循环系统稳定运行。

---

## 二 · 心智模型

把"循环"比作"工厂流水线":
- **生产节拍**: 循环的速度
- **超调**: 走过头
- **震荡**: 不稳定
- **死锁**: 卡死
- **漂移**: 慢慢偏离目标

**Loop Engineering = 五大节拍 + 失控检测 + 闭环修复**。

## 三 · 章节主线 (5 段)

### 第 1 段 · OS Loop (10 分钟)

#### 3.1.1 操作系统循环

操作系统是**最古老的循环系统**:
- **调度循环**: 调度器不停选下一个进程
- **中断循环**: 等待中断 → 处理 → 返回
- **时钟循环**: 时钟中断 → 进程切换
- **IO 循环**: epoll / select / IOCP

#### 3.1.2 调度循环的代表

```python
# Linux CFS 调度核心 (简化)
while True:
    # 选下一个 task
    next_task = pick_next_task(runqueue)
    if next_task:
        context_switch(current, next_task)
    # 中断返回后
    current = next_task
```

#### 3.1.3 OS Loop 失败模式

| 失败 | 原因 | 防御 |
|------|------|------|
| **优先级反转** | 低优先持锁, 高优先等待 | 优先级继承 |
| **饥饿** | 高优先永远抢 | 时间片老化 |
| **死锁** | 4 条件齐 | 银行家算法 |
| **活锁** | 互相让资源 | 退避 + 随机 |
| **调度抖动** | 频繁切换 | 时间片大小 |

#### 3.1.4 工程指南

- **时间片**: 1-10ms (Linux 默认 4ms)
- **队列深度**: 限制 (避免抖动)
- **背压**: 主动丢弃 / 限流
- **观测**: perf / BPF / eBPF

### 第 2 段 · RL Loop (10 分钟)

#### 3.2.1 强化学习闭环

```
环境 s → Agent 决策 a → 奖励 r + 新 s' → 训练 → 改进策略
   ↑                                              ↓
   └──────────────────────────────────────────────┘
```

#### 3.2.2 RL Loop 的核心算法

| 算法 | 循环模式 | 频率 |
|------|----------|------|
| **回合制** | 整局结束才更新 | 慢 |
| **步进** | 每步更新 | 中 |
| **批量** | 收集 N 步更新 | 快 |
| **分布式** | 多 worker 并行 | 极快 |

#### 3.2.3 RL Loop 失败模式

| 失败 | 原因 | 防御 |
|------|------|------|
| **策略崩溃** | 极端动作 | 熵正则 |
| **Reward Hacking** | 钻漏洞 | KL 约束 |
| **Catastrophic Forgetting** | 学新忘旧 | 经验回放 |
| **Off-policy 发散** | 数据分布差 | 信赖域 (TRPO) |
| **Reward 稀疏** | 学习信号弱 | Curiosity / HER |

#### 3.2.4 PPO 循环

```python
for iteration in range(10000):
    # 1. 收集 G 条轨迹
    for env in envs:
        trajectory = collect(env, policy)
    # 2. 计算 advantage
    advantages = compute_gae(trajectories, value_net)
    # 3. PPO 更新
    for _ in range(K_epochs):
        loss = ppo_loss(policy, trajectories, advantages)
        optimizer.zero_grad(); loss.backward(); optimizer.step()
    # 4. 评估
    if eval_mean_reward > target:
        break
```

### 第 3 段 · Agent Loop (10 分钟)

#### 3.3.1 LLM Agent 闭环

```
Thought → Action → Observation → Thought → ...
   ↑                              ↓
   └──────────────────────────────┘
```

#### 3.3.2 Agent Loop 三种模式

| 模式 | 适用 | 例子 |
|------|------|------|
| **ReAct** | 通用 | Thought/Action/Obs |
| **Reflexion** | 自我反思 | 失败 → 反思 → 重试 |
| **Plan-Execute** | 复杂任务 | 先规划再执行 |

#### 3.3.3 Agent Loop 失败模式

| 失败 | 原因 | 防御 |
|------|------|------|
| **无限循环** | verifier 不收敛 | max_iter 限制 |
| **幻觉** | LLM 编造 | fact-check step |
| **Tool 误用** | 参数错 | 严格 schema |
| **State 漂移** | 上下文膨胀 | 周期压缩 |
| **观测黑盒** | 无 trace | OpenTelemetry |

#### 3.3.4 max-iter 与保险

```python
def agent_loop(query, max_iter=10):
    state = State(query=query)
    for i in range(max_iter):
        # 1. LLM 决策
        action = llm.invoke(state)
        # 2. 执行
        observation = execute(action)
        # 3. 验证
        if is_done(observation):
            return observation
        # 4. 更新
        state.update(action, observation)
    raise MaxIterError("Agent 循环超限")
```

#### 3.3.5 Reflexion 自我反思

```
循环 1: 失败 → 反思 "为啥错"
循环 2: 用反思 → 改进
循环 N: 收敛
```

自反思让 Agent **不会再犯同样错**。

### 第 4 段 · DevOps Loop (10 分钟)

#### 3.4.1 CI/CD 闭环

```
Code → Build → Test → Deploy → Monitor → (回到 Code)
```

#### 3.4.2 常见 DevOps Loop

| 工具 | 循环 | 频率 |
|------|------|------|
| **GitHub Actions** | push → CI → deploy | 每次 push |
| **Airflow** | DAG 调度 | 定时 |
| **Prefect** | 工作流 | 事件 |
| **Dagster** | 数据资产 | 事件 |
| **Argo** | K8s 工作流 | 声明 |
| **Cron** | 定时任务 | 定时 |

#### 3.4.3 DAG 编排

**Airflow DAG**:
```python
@dag(schedule="@daily", start_date=datetime(2024, 1, 1))
def etl_pipeline():
    raw = extract()
    clean = transform(raw)
    load(clean)

etl_pipeline()
```

#### 3.4.4 DevOps Loop 失败模式

| 失败 | 原因 | 防御 |
|------|------|------|
| **状态丢失** | crash 中断 | persistent state |
| **超时** | 任务长 | timeout + retry |
| **资源耗尽** | 并发高 | backpressure |
| **回滚失败** | 部署不一致 | GitOps |
| **监控黑洞** | 不知故障 | distributed tracing |

#### 3.4.5 GitOps 闭环

```
Git 仓库 (single source)
    ↓ git push
Kubernetes (自动 apply)
    ↓ diff
ArgoCD (自动 sync)
```

**优势**: 任何状态都来自 Git, 可回滚。

### 第 5 段 · Control Loop (10 分钟)

#### 3.5.1 经典控制闭环

```
传感器 → 反馈 → 控制器 → 执行器 → 物理
   ↑                              ↓
   └────────────── 状态 ←──────────┘
```

#### 3.5.2 PID 控制

**核心公式**:
$$u(t) = K_p e(t) + K_i \int_0^t e(\tau) d\tau + K_d \frac{de(t)}{dt}$$

- **P (比例)**: 当前误差
- **I (积分)**: 累积误差 (消除稳态)
- **D (微分)**: 误差变化率 (抑制震荡)

#### 3.5.3 在 AI 中的应用

**RLHF 的 Preference Loop**:
```
人类评分 → 偏好对 → RM 训练 → 反馈 → 改进 LLM
```

**GRPO Loop**:
```
采样 G 回答 → 计算 $A_i$ (组内优势) → PPO-clip 更新 → 改进
```

**Test-Time Compute Loop**:
```
用户输入 → CoT 推理 → 验证 → 重采样 → 输出
```

#### 3.5.4 Control Loop 失败模式

| 失败 | 原因 | 防御 |
|------|------|------|
| **超调** | P 太大 | 降低 P |
| **震荡** | D 太小 | 加 D |
| **稳态误差** | I 缺失 | 加 I |
| **不稳定** | 系统非线性 | 增益调度 |
| **延迟** | 控制系统慢 | 预测控制 |

#### 3.5.5 PID 调参经验

| 现象 | 调整 |
|------|------|
| 响应慢 | 加 P |
| 震荡 | 减 P / 加 D |
| 残留误差 | 加 I |
| 慢收敛 | 全部微调 |

| Loop | 周期 | 频率 | 工具 | 致命失败 |
|------|------|------|------|----------|
| **OS Loop** | ms-s | 1000Hz | 调度器 | 死锁 |

## 五 · 9 类共同失败模式

| 失败 | 含义 | 防御 |
|------|------|------|
| **无限循环** | 没终止 | max_iter |
| **死锁** | 互相等 | 超时 + 排序 |
| **活锁** | 互相让 | 随机 + 退避 |
| **漂移** | 慢慢偏离 | 周期校准 |
| **超调** | 走过头 | 限幅 |
| **震荡** | 不稳定 | 滤波 |
| **稳态误差** | 终点偏 | 积分 |
| **响应慢** | 周期长 | 优化 |
| **观测黑盒** | 不知状态 | tracing |

## 六 · 工程原则 (5 大)

1. **可终止 (terminable)**: 任何循环必须有终点
2. **可观测 (observable)**: 状态可见
3. **可回退 (recoverable)**: 失败可回滚
4. **可限速 (rate-limited)**: 防止失控
5. **可校准 (calibratable)**: 周期校准
